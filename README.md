# 실시간 이상거래 탐지 시스템 (FDS)

한국 전자금융 계좌이체 거래 **120,000건**에서 **13개 사기 유형**을 분류하고,
탐지된 거래를 **사람이 판정하고, 그 판정이 다시 임계값에 되먹이는** 한 벌의 시스템입니다.

분석(LightGBM 13-class · Macro-F1 0.6138)에서 끝나지 않고,
**무인 워처 + QA 대시보드 + 관제 콘솔**까지 운영 가능한 형태로 만들었습니다.

| | |
|---|---|
| **팀** | 쉽(10)네? — 박근우(팀장) · 안영진 · 이태민 · 이혜진 |
| **데이터** | [DACON 금융 AI 챌린지](https://dacon.io/competitions/official/236297/data) · 120,000행 × 64컬럼 · 13클래스 |
| **모델** | LightGBM 13-class · 58피처 · **Macro-F1 0.6138** |
| **운영 임계값** | `th_review` **0.005** — 기대비용 **4.62억** (Macro-F1 ≥ 0.60 제약 하 최소) |
| **시스템** | Python **36,477줄** · Streamlit 앱 2개 + 워처 · `pipeline/` 40모듈 · 자가검증 12종 |
| **다국어** | KO / EN / JA / ZH — 657키 × 4 |

## 이 저장소가 말하는 것 — 조용한 실패와 싸운 기록

이 프로젝트에서 시간을 잡아먹은 버그는 **하나도 예외를 던지지 않았습니다.**

스택 트레이스가 뜨는 버그는 5분이면 고칩니다.
문제는 **화면이 멀쩡히 그려지고, 저장도 되고, 로그도 남는데, 값이 틀린** 것들이었습니다.

| 증상 | 진짜 원인 | 왜 못 잡았나 |
|---|---|---|
| Macro-F1 **0.7103** — 좋아 보였다 | `is_fraud` 라벨 누수 | **성능이 올라간다.** 나빠져야 의심한다 |
| 전 지표가 **정확히 0.0** | 정수 클래스(`0~12`) vs 문자 라벨(`a~m`) | 0.0 은 "모델이 나쁘다"로 읽힌다 |
| **보이는 본문 ≠ 발송 본문** | Streamlit 은 `key` 가 있으면 `value=` 를 무시 | 화면도 발송도 성공한다. **3번 재발** |
| 재검증이 "성공"한다 | 마스킹본으로 예측 → 전처리가 기본값으로 메움 | **예외 없이 숫자가 나온다** |
| 시간대 판별이 전부 오진 | `strftime()` 이 TEXT 반환 → 비교가 **항상 참** | SQLite 타입 서열은 안 보인다 |
| 경보가 절반으로 줄었다 | 슬라이더 `step=0.01` 이 운영값 `0.005` 를 못 만듦 | 저장도 되고 로그도 남는다 |
| 판정 이력이 사라진다 | `detections` UPSERT | 최신 값은 멀쩡히 있다 |
| 예측이 매번 랜덤 | 더미 모드 **15% 확률 랜덤 사기 판정** | 반환값으로 진짜와 구분 불가 |

**개별 수정으로는 재발을 못 막았습니다.** 같은 버그가 3번 재발한 뒤 방식이 바뀝니다 —
불변식을 테스트로 고정하고, 정적 검사로 차단하고, 구현을 한 벌로 합치고, **폴백을 금지**했습니다.

## 핵심 결과

### 분석

- **정확도의 함정을 정면으로 다뤘습니다** — 전부 정상으로 예측해도 Accuracy 98.92%.
  그때 Macro-F1 은 **0.0765**. 주 지표를 Macro-F1 로 고정했습니다.
- **13클래스 통합검정만으로는 변수를 버리면 안 됩니다** — `Distance` 는 통합검정에서
  ε²=0.0023(negligible)이지만, 정상 대비 `a` 유형 1:1 재검정에서는 **Cliff's δ=0.95(large, 전체 최댓값)**.
  → **정상 대비 이진 재검정을 병행**하는 2단계 통계 설계.
- **라벨 누수를 스스로 찾아 성능을 0.0965 떨어뜨렸습니다** — 0.7103 → **0.6138**.
  발표자료 본문에 Before/After 로 실었습니다.
- **그룹 누수 0건** — 개인식별자 41% · 계좌 24%가 여러 유형에 걸쳐 등장.
  `StratifiedGroupKFold` 로 고객·계좌 누수를 각각 0으로 만들었습니다.
- **파생변수 7종이 SHAP 으로 검증됐습니다** — `Transaction_is_withdrawal` **1위**(0.4471),
  `Transaction_Amount_abs` 3위, `Amount_vs_monthly_max_ratio` 5위.

### 의사결정

- **임계값을 성능이 아니라 기대비용으로 정했습니다.**
  미탐 1,700만원 vs 오탐 5천~5만원 = 최대 **340배** 비대칭.
  `Macro-F1 ≥ 0.60` 제약 하 비용 최소 → **thr 0.005 · 4.62억**.
- **순수 비용최소화의 함정을 문서화했습니다** — 제약 없이 비용만 최소화하면
  Macro-F1 이 0.469 로 무너지고, 임계값 0(전량 의심)은 오히려 **11.8억**으로 폭증합니다.
- **결론의 견고성** — 오탐 1건이 **425만원**(가정의 85배)은 되어야 이전 값이 이깁니다.
- **단정하지 않았습니다** — 0.005 / 0.008 / 0.01 의 차이는 미탐 5건 이내로,
  사기 258건 표본에서는 분산 범위일 수 있다고 명시했습니다.

### 검증된 "안 한다" 3건

계획하거나 권고받은 것을 **구현해 보고 수치로 기각**한 기록입니다.

| 시도 | 출처 | 결과 |
|---|---|---|
| **2단계 계층 분류** | 기획서 예상결과물 1번 | Macro-F1 **0.6105** — 한방 기본(0.6138)보다도 낮음. 1단계 FN 이 **영구 미탐**으로 굳는 오류 전파 |
| **규칙 기반 + ML 결합** | 튜터 권고 | override **−0.0040** · boost 0.0000. 유형별 최고 precision 이 대부분 0.2 미만 |
| **생성 AI 합성 증강** | 기획서 목표 · 멘토 권고 | CTGAN **−0.0928** · TVAE −0.0371 · SMOTE −0.0466. **few-shot 문제를 few-shot 데이터로 풀 수 없다** |
| **이상점수(ISF) 피처 결합** | 기획서 M5 | **−0.0084**. LightGBM 이 이미 훨씬 정교하게 판단 중 (PR-AUC 0.933 vs 0.025) |

### 시스템

- **판정 엔진을 하나로 모았습니다** — `DetectService` 하나에 대시보드·워처 두 어댑터가 붙어 있고,
  두 앱이 같은 입력에 **같은 판정**(`d / 0.8773517059743291`)을 내는 것을 테스트로 고정했습니다.
- **정답을 모르는 운영 상황을 설계했습니다** (튜터 지적 대응) —
  담당자 판정 큐 · **판정 시점 스냅샷** · 미탐 직접 등록 창구 · 실제 판정 기반 임계값 시뮬레이터.
- **알람은 과해서 죽는다는 것을 전제로 만들었습니다** — 실측 소음 예보를 토글 옆에 표시하고
  (기본 설정 하루 3.1회 중 헛알람 1.1회), 억제 장치 5종을 넣었습니다.
- **못 하는 것을 화면에 그렸습니다** — 임계값 시뮬레이터의 데이터 없는 구간은 회색 점선.
  *그냥 그리면 그럴듯한 거짓말이 되기 때문입니다.*

### 남은 자료로 되살린 것

원본과 최종 결과는 있는데 **중간 과정이 통째로 비어 있던 구간**이 있었습니다.
1·2차 전처리 노트북, Baseline 비교 코드, ISF 코드가 전부 없었습니다.
남은 데이터로 **실제로 다시 돌려** 복원했습니다 → [`docs/09`](docs/09_reconstruction_log.md)

- **역사적 수치가 재현됩니다** — 발표의 `0.7103` 이 **2차 61피처 + `is_fraud` 누수** 값임을 확정
  (재현 0.7053, 미탐 0 · 오탐 0). 3차 `0.6138` · `0.6395` 는 **소수점까지 완전 일치.**
- **3차가 1차보다 0.07 낮다는 것을 발견했습니다.** 어느 문서에도 없던 사실입니다.
  절제 실험으로 원인을 특정했습니다 — **날짜차 4종 + 위협집계 5종**이 함께 사라졌습니다.
- **되살리면 회복됩니다** — 최고 Macro-F1 `0.6395 → 0.6779`.
  특히 **`l` 유형 F1 `0.083 → 0.267` (3.2배)** — 발표자료가 '다음 과제 최우선'으로 지목한 유형입니다.
- **사라진 9피처의 생성 공식을 원본에서 역산해 9/9 전부 100% 확정**했습니다. 바로 쓸 수 있습니다.

> ⚠️ 이 수치들은 valid 홀드아웃에서 여러 구성을 비교해 고른 것이라 **선택 편향이 있습니다.**
> 결론은 *"이만큼 오른다"* 가 아니라 **"9피처가 실질 신호였고 되살릴 가치가 있다"** 입니다.

### 알려진 한계 (숨기지 않습니다)

| 한계 | 내용 |
|---|---|
| **`l` 유형 탐지 실패** | Recall **0.048**. 신호(`Customer_Birthyear`)는 SHAP 1위인데 학습 100건 few-shot. **9피처 복원이 유력 처방** |
| **피처 세대 퇴행** | 3차 58피처가 1차 81피처보다 **0.07 낮다.** 1차→2차 재설계에서 33개를 뺀 **의사결정 기록이 없다** |
| **유형 정확도 53.5%** | 탐지는 82.9%지만 유형 특정은 절반. `e·f·g` 신호 유사 |
| **look-ahead 5피처** | 명세 해석으로 유지했으나 **미확정**. 코드가 매 실행 경고를 띄운다 |
| **인증 없음** | ngrok URL 을 아는 누구나 조회·발송 가능. **운영 전환 전 필수** |
| **실데이터 미검증** | 임계값은 검증셋(과거) 기준 |
