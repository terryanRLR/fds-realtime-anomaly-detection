# 분석 결과 프롬프트 양식 가이드
> FDS QA 검증 시스템 — LLM 출력 표준 양식 문서

---

## 1. 최종 확정 양식

오빠 초안을 기반으로 6개 섹션으로 확장했다.

| 섹션 | 오빠 초안 | 확정 양식 | 변경 이유 |
|------|----------|----------|----------|
| 제목 | `? 형 문제 발생!` | `⚠️ {유형}형 이상거래 탐지 — {유형명}` | 위험 수준 한눈에 파악 |
| 데이터 이름 | 거래 식별 + 마스킹 | 동일 (계좌·IP·MAC까지 마스킹 확장) | 개인정보 보호 강화 |
| KPI | 5개 값 | 표 형식 (현재값/정상기준/평가) | 비교 가능해야 판단 가능 |
| 판정 이유 | 단순 작성 | 근거 기반 서술 + RAG 인용 | 신뢰성 확보 |
| 권장 조치 | 단순 작성 | 즉시/단기/장기 3단계 | 실무 적용성 향상 |
| **신규: 이상 패턴 요약** | — | 불릿 3개 | 빠른 스캔용 |
| **신규: 오탐 가능성 체크** | — | 체크리스트 | FP 비용 절감 |

---

## 2. 최종 출력 양식 (실제 생성 예시)

```
⚠️ E형 이상거래 탐지 — ATM 전용 고액 출금 (계좌정지 + 1천만원↑)

【판정 근거】
위험 점수 0.9999로 E형 사기 패턴이 탐지되었습니다. 거래 금액
85,000,000원 출금, 채널 ATM, 거래 거리 480km 등 주요 지표가
해당 사기 유형의 특성과 일치합니다. RAG 참고 문서에 따르면
ATM + 1천만원↑ + 계좌정지 조합은 정상 거래에서 거의 발생하지
않는 패턴입니다.

【이상 패턴 요약】
• 루팅/탈옥 단말 + VPN 동시 감지
• 30일 내 계좌 거래정지 이력 존재
• 미사용 단말에서 1천만원 이상 출금 시도

【오탐 가능성 체크】
- 고객 해외 체류 여부: 확인 필요
- 신규 단말 등록 여부: 해당 없음 (장기 미사용 단말)
- 계좌정지 해제 직후 본인 거래 여부: 확인 필요

【권장 조치】
즉시: ATM 거래 자동 차단
단기: 고객 본인 확인 전화 (5분 이내)
장기: 계좌정지 해제 후 72시간 모니터링 정책 적용
```

## 4. KPI 자동 선별 로직

`extract_key_kpis()` 함수가 row에서 자동으로 5~6개 핵심 지표를 뽑는다.

```
1. 위험 점수          (항상 포함)
2. 거래 금액           (절대값 1천만원 기준 평가)
3. 거래 거리           (200km 기준 평가)
4. 접속 실패 횟수      (2회 기준 평가)
5. 동일 계좌 이체 횟수  (2회 기준 평가)
6. 활성화된 위험 플래그 (1개 이상 시 추가 — 19종 플래그 자동 스캔)
```

기준값은 `analysis_prompt.py` 상단에서 직접 수정 가능하다.

## 6. 사용 방법

### 기본 사용 (자동 연동됨)
`llm_analyzer.py`가 `prompts/analysis_prompt.py`를 자동으로 import해서 사용한다. 별도 설정 불필요하다.

```python
from pipeline.llm_analyzer import LLMAnalyzer

analyzer = LLMAnalyzer()
result = analyzer.analyze(row, fraud_type, risk_score, rag_context)

result['analysis']  # 분석 리포트
result['slack']      # Slack 메시지
result['email']      # 이메일 본문
result['ctx']        # 구조화 데이터 (대시보드 표시용)
```

### 양식 직접 수정하고 싶을 때
`prompts/analysis_prompt.py`의 `build_analysis_prompt()` 함수 내 `[출력 형식]` 섹션을 수정하면 된다.

```python
# 예: 오탐 체크 섹션 제거하고 싶다면
def build_analysis_prompt(ctx: dict) -> str:
    return f"""...
【권장 조치】
...
"""  # 【오탐 가능성 체크】 블록만 삭제
```

### KPI 기준값 조정
```python
# analysis_prompt.py 내 extract_key_kpis() 함수에서
'평가': '⚠️ 고액' if abs(amount) > 10_000_000 else '✅ 정상범위',
#                              ↑ 이 값을 조직 기준에 맞게 수정
```

## 7. LLM 미연결 시 동작 (폴백)

llama.cpp 서버가 꺼져 있거나 API 키가 없어도 시스템은 멈추지 않는다. `llm_analyzer.py`의 `_build_fallback_*()` 함수들이 동일한 양식 구조로 즉석 메시지를 생성한다.

```
llama.cpp 시도 → 실패
        ↓
Anthropic API 시도 → 키 없음
        ↓
폴백 메시지 생성 (양식 동일, 내용은 row 데이터 기반 자동 조립)
```

발표 시연 중 LLM 서버가 불안정해도 대시보드는 계속 정상 작동한다.

## 8. 검증 결과

실제 고위험 시나리오(루팅+VPN+계좌정지+1천만원↑)로 테스트한 결과:

```
ML 예측: 유형 E / 위험점수 0.9999  ← 정확히 탐지
LLM 폴백: 양식 그대로 생성 완료
Slack: 🔴 CRITICAL 레벨 자동 부여
이메일: 구조화 양식 정상 출력
```

LLM이 연결되면 더 풍부한 서술형 문장으로 대체되지만, 양식 구조(섹션 순서·KPI 표·오탐 체크리스트)는 동일하게 유지된다.
