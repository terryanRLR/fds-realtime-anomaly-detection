# 【v5.3】 팀 실사용 피드백 대응 (2026-07-06)

## 팀 모델 로드 오류 3종 — 원인 진단
`invalid load key`는 **버전 문제가 아니라 파일 형식 문제**입니다 (pickle이 아닌 바이트).
버전 불일치(sklearn 1.7.2 / lgbm 4.6.0 등)는 ModuleNotFoundError/AttributeError 계열로
따로 나타나며, 이 경우 별도의 안내 메시지를 표시합니다.

| 오류 | 실제 원인 | v5.3 대응 |
|---|---|---|
| invalid load key '\x0a' | ONNX/protobuf 또는 선두 개행 텍스트를 .pkl로 저장 | 헤더 스니핑 → ONNX 자동 로드(권장 안내) / 텍스트는 정리 후 재시도 |
| invalid load key '\x05' | pickle이 아닌 바이너리 | joblib → LightGBM 네이티브 → ONNX 순 재시도, 전부 실패 시 저장 권장 방법 안내 |
| 'dict' has no predict_proba | {'model':…} 번들 저장 | model/clf/estimator 등 관례 키 + 값 탐색으로 내부 모델 자동 추출 |
| (추가) LightGBM 네이티브 .txt | booster.save_model 텍스트 | Booster 래핑 + le_target.pkl로 클래스 라벨 복원 |
| (추가) 깨진 pkl로 인한 s2.eval_fail | MLClassifier가 FileNotFoundError만 격리 | 모든 로드 실패를 더미 모드로 격리 + 사유 로그 |

검증: joblib/선두개행 native/dict 번들 → 원본과 **확률 오차 0.0** 일치,
ONNX 오인 확장자 자동 감지 로드, 불량 파일은 안내형 에러, 세 형식 동시 동적 평가 F1 동일.

# 【v5.4】 피처 호환성 확장 + 세션 2 정비 + 비율 토글 (2026-07-06)

## 피처 불일치 오류 — 진단과 대응
`number of features (81) != training (48)` / `feature names should match` 원인:
**48피처(원본)로 학습한 모델에 81피처(전처리 완료 parquet)를 입력**한 조합.
검증 결과 81피처 셋에 원본 48피처 중 46개가 이름 그대로 포함 → 자동 매칭 가능.

**✨ 자동 피처 매칭 (evaluator v5.4)** — 모델별로:
1. 모델이 기억하는 학습 피처명(feature_names_in_/feature_name_/Booster) 조회
2. 데이터셋에서 이름 기준 선택·재정렬 (sklearn 'feature names' 오류 해소)
3. 누락 피처(≤20%)는 feature_defaults.json 값으로 대체 + 화면에 노트 표시
   ("자동 피처 매칭 적용 — 누락 피처 2개 기본값 대체(…)")
4. 누락 과다(>20%) = 계열이 다른 조합 → 해당 모델만 명확한 사유로 격리
5. 피처명 없는 형식(ONNX)은 차원 검증 후 안내

검증: 48피처 lgbm/lr × 81피처 parquet → **양쪽 모두 평가 성공**(노트 표시),
역방향(81피처 모델 × 원본 CSV)은 "35개 누락 — 계열 다름" 격리 + 나머지 정상.
⚠ 대체된 피처는 상수가 되므로 해당 모델 성능은 참고치 — 정밀 비교는 계열 일치 데이터셋 권장(노트로 항시 표시).

## 세션 2 정비

  → 높이 0 막대가 보이지 않았던 것. 값 라벨(0.00 명시) + support 호버 +
  "⚠ F1=0 유형: A(22건) — 전혀 정탐하지 못함" 경고 배너 + Macro avg 캡션 추가.
- 평가 실패 모델을 F1 0.0으로 위장하지 않고 ⚠ 오류 카드로 구분 표시.
- 클래스 리포트 범례를 플롯 밖 우상단으로 (v5.3 플래그 차트와 톤 통일).

두 모델 모두 48피처로 정상이나, **classes_가 'a'~'m'이 아닌 정수 0~12** (y를 인코딩한 채 fit).

3. **⚡ 배치 전처리 벡터화**: 원본형 데이터셋 동적 평가의 행별 루프(5,000행 ≈ 수 분)를

# 【v6.2】 세션 2 자동 호환 + 세션 5 배치 UI 개편 (2026-07-07)

## 세션 2 — "train.csv에서 🧩 컴포지트가 스킵되던 문제" 근본 해결
**원인**: evaluate가 단일 프렙(48피처 MLClassifier)을 모든 모델에 일괄 적용 → 81피처 모델은 35개 누락으로 스킵.
**해법**: `evaluate(preprocess_fn=None, bridge=...)` — 모델별 자동 프렙:
  · 기대 피처 전부 존재 → passthrough
  · 소량 누락 → 피처 매칭 + 기본값 대체
  · **대량 누락 + 브리지 → 브리지 변환 후 피처 매칭** ← 핵심
  · 브리지 없음 → MLClassifier 전처리 후 피처 매칭
→ **train.csv 하나로 48/81피처 모델을 동시에 평가** (노트 표시: "🌉 브리지")
→ 사전 스킵 로직 제거 (evaluate 내부 격리로 충분)

검증: train.csv × 🧩 한방(F1 0.9193, 🌉 브리지) + 🧩 2단계(F1 0.7324, 🌉 브리지) 동시 성공.

# 【v6.5】 4대 신규 기능 (2026-07-09)

## 1. 세션 1 — 선택 데이터셋 동적 KPI
사이드바에서 선택한 데이터셋(train.csv / parquet:va 등)에 따라 세션 1의
전체 건수 · 정상 비율 · 사기 건수/유형 수 · 피처 수가 **실시간 변동**.
데이터셋 이름·행 수·비고가 캡션으로 표시되어 어떤 데이터를 보는지 명확.

## 2. 분석 결과 TTS 읽어주기
- 사이드바 "🔊 음성·알람"에서 TTS 언어 선택 (한국어/English/日本語/中文)
- 배치 분석 결과에 "🔊 분석 결과 읽어주기" 버튼 → 브라우저 내장 Web Speech API로 로컬 재생
- 추가 설치 불필요 (Chrome/Edge/Safari 내장 TTS 엔진 자동 사용)
- 3,000자 제한 (긴 보고서는 앞부분만 읽음)

## 3. 위험 감지 경고 알람
- 사이드바 "🔔 위험 감지 알람" 토글 (ON/OFF)
- 단건 탐지: 이상거래 판정 시 880Hz→1100Hz 2연타 비프 (Web Audio API)
- 배치 분석: 이상거래 1건 이상 시 동일 알람
- 브라우저 오디오 정책상 사용자가 페이지와 1회 이상 상호작용(클릭) 후 재생

## 4. 탐지 결과 DB 자동 구축
- `fds_results.db` → `detections` 테이블에 단건/배치 결과 자동 적재
- 스키마: transaction_id(PK) · fraud_type · risk_score · is_anomaly · model · threshold · detected_at · raw_json
- **중복 갱신**: 동일 transaction_id 재탐지 시 INSERT ON CONFLICT UPDATE → 최신 판정으로 교체
- 배치 리롤 시에도 행 수 불변 (3건→3건, 중복 없음 검증됨)
- 향후 대시보드 세션에서 DB 조회·통계·시계열 분석 가능 (확장 준비)

게이트: 동적 KPI / TTS·알람 렌더 / DB 3건 적재 / 리롤 중복 갱신 / 전 세션 회귀 — 통과.
