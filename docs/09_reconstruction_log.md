## R-1. 전처리 1차·2차 노트북 — 결과만 남고 과정이 없었다

**비어 있던 것**
`data/` 에 세 세대의 parquet 이 있는데, 노트북은 **3차 것 하나뿐**이었습니다.

```
data/구구 X_tr.parquet   81피처   ← 1차   노트북 없음
data/구  X_tr.parquet    61피처   ← 2차   노트북 없음
data/    X_tr.parquet    58피처   ← 3차   FDS_전처리_정리본.ipynb ✅
```

`reports/09`(2차 전처리 파일 생성)에 *"파생변수 7종 추가"* 정도만 적혀 있고,
1차 → 2차에서 무엇이 왜 바뀌었는지는 어디에도 없었습니다.

**복원 방법**
세 세대를 **완전히 같은 조건**(LightGBM 300트리 · `class_weight="balanced"` · seed 42)으로
재학습하고, 컬럼 집합을 대조했습니다.

**결과 — 역사적 수치가 재현됩니다**

| 기록 | 출처 | 재현값 | 판정 |
|---|---|---|---|
| Macro-F1 **0.7103** (중간보고) | 발표자료 p.8 | **0.7053** — 2차 61피처, `is_fraud` 포함 | ✅ |
| 2차 정식 최고점 **0.646** @thr=0.1 | `reports/13` | **0.6464** @thr=0.1 | ✅ |
| 3차 argmax **0.6138** | `models/model_meta.json` | **0.6138** | ✅ 완전 일치 |
| 3차 최고점 **0.6395** @thr=0.03 | 발표자료 p.37 | **0.6395** @thr=0.03 | ✅ 완전 일치 |

**새로 확정된 사실**

1. **`is_fraud` 누수는 2차에서 발생했습니다.** 1차 parquet 에는 없고, 2차에 들어왔다가, 3차에서 제거됐습니다.
   → 기존 문서가 "2차 → 3차 전환의 이유"로 적은 것이 정확했음이 확인됐습니다.
2. **누수 모델은 미탐 0 · 오탐 0** 입니다. 정답 라벨을 피처로 줬으니 valid 를 완벽히 맞힙니다.
   0.7103 은 성능이 아니라 **답안 유출**입니다.
3. **2차 → 3차는 순수 제거**입니다 (추가 0개).
   빠진 셋: `is_fraud`(누수) · `Is_dawn`(`Transaction_Hour` 와 중복) ·
   `weak_signal_composite_score`([`03a` #A-9](03a_issues_data_modeling.md#a-9) 의 그 피처).
4. **1차 → 2차는 재설계**입니다 (33 제거 / 13 추가). 같은 계보로 볼 수 없습니다.

## R-2. 3차가 1차보다 낮은 이유 — 절제 실험으로 특정

**문제 제기**
재학습해 보니 **1차(81피처)가 3차보다 높았습니다.**

| 세대 | 피처 | argmax | 최고 |
|---|---|---|---|
| 1차 | 81 | **0.6844** | **0.7062** |
| 3차 | 58 | 0.6138 | 0.6395 |

누수 없이 0.07 차이입니다. **전처리를 거듭할수록 성능이 떨어진 것**인데,
그 사실이 어느 문서에도 기록돼 있지 않았습니다.

**복원 방법**
1차에만 있는 피처를 그룹으로 묶어 하나씩 빼고 재학습했습니다.

**결과**

| 절제 | 피처 | argmax | Δ | 해석 |
|---|---|---|---|---|
| ① 1차 전체 (기준선) | 81 | 0.6844 | — | |
| ② − 빈도 인코딩 `*_freq` 3 | 78 | 0.6905 | **+0.0061** | **노이즈였다** |
| ③ − 날짜차 파생 4 | 77 | 0.6508 | **−0.0336** | 실질 신호 |
| ④ − `Location_sigungu` | 80 | 0.6944 | **+0.0100** | **노이즈였다** |
| ⑤ − 위협 집계 5 | 76 | 0.6423 | **−0.0421** | **가장 큰 손실** |
| ⑥ − 위 4그룹 전부 | 68 | 0.6552 | −0.0292 | |
| ⑦ 1차∩3차 공통 48피처만 | 48 | 0.6120 | −0.0724 | **≈ 3차(0.6138)** |
| ⑧ 3차 전체 | 58 | 0.6138 | −0.0706 | |

**결론**

- 3차가 **잘 뺀 것**: `IP_Address_freq` 등 빈도 인코딩과 `Location_sigungu`.
  실측으로 **노이즈**였고, 빼니 오히려 올랐습니다. 고카디널리티 식별자 인코딩을 버린 것은 옳은 판단입니다.
- 3차가 **잃은 것**: 날짜차 파생 4종(−0.034)과 위협 집계 5종(−0.042).
  **이 둘이 3차 성능 하락의 원인**입니다.
- ⑦이 결정적입니다 — 공통 48피처만 남기면 0.6120 으로 **3차(0.6138)와 사실상 같습니다.**
  3차가 새로 넣은 파생(`Amount_vs_*` 등)은 잃은 것을 상쇄하지 못했습니다.

## R-3. 사라진 9피처 — 복원하면 회복되는가, 공식은 무엇인가

### 복원 실험

세 세대가 **같은 StratifiedGroupKFold 분할**임을 먼저 검증했습니다
(`y_tr`·`y_va` 가 행 단위로 완전 일치). 그래서 1차의 컬럼을 3차에 안전하게 이식할 수 있습니다.

| 구성 | 피처 | argmax | 최고 Macro-F1 | Δ최고 |
|---|---|---|---|---|
| 3차 현행 | 58 | 0.6138 | 0.6395 | — |
| + 날짜차 파생 4 | 62 | 0.6210 | 0.6575 | +0.0180 |
| + 위협 집계 5 | 63 | 0.6488 | 0.6669 | +0.0274 |
| **+ 둘 다** | **67** | 0.6470 | **0.6779** | **+0.0384** |

**유형별 변화가 더 중요합니다.**

| 유형 | 현행 F1 | 복원 후 | Δ | 비고 |
|---|---|---|---|---|
| **`l`** | **0.0833** | **0.2667** | **+0.1834** | **발표자료 '다음 과제 최우선'** |
| `g` | 0.4000 | 0.5652 | +0.1652 | 확신도 낮음 |
| `e` | 0.5333 | 0.6957 | +0.1624 | |
| `c` | 0.3784 | 0.5128 | +0.1344 | 확신도 낮음 |
| `h` | 0.6667 | 0.7500 | +0.0833 | |
| `f` | 0.8000 | 0.8485 | +0.0485 | |
| `j` | 0.5405 | 0.5263 | −0.0142 | |
| `a` | 0.9778 | 0.9545 | −0.0233 | |
| `k` | 0.7742 | 0.7500 | −0.0242 | |
| `b` | 0.7805 | 0.7143 | −0.0662 | |
| `i` | 0.7027 | 0.6286 | −0.0741 | |
| **`d`** | 0.3429 | 0.2000 | **−0.1429** | 확신도 낮음 — **악화** |

> **확신도 '낮음' 4개 중 `l`·`g`·`c` 세 개가 크게 개선되고, `d` 만 악화됩니다.**
> 발표자료가 최우선 과제로 지목한 `l` 유형(Recall 0.048 · 사실상 탐지 실패)이
> F1 기준 **3.2배** 올라갑니다.

### ⚠️ 이 수치를 인용할 때의 한계

이 실험은 **valid 홀드아웃에서 여러 구성을 비교해 고른 것**입니다.
따라서 `+0.0384` 에는 **valid 에 대한 선택 편향이 포함**돼 있습니다.
실제 채택하려면 별도 테스트셋 또는 교차검증으로 재확인해야 합니다.

이 실험의 결론은 *"이만큼 오른다"* 가 아니라
**"3차에서 빠진 9피처가 노이즈가 아니라 실질 신호였고, 되살릴 가치가 있다"** 입니다.

### 공식 역산 — 9/9 전부 100% 일치 확정

1차 전처리 코드가 없으므로, 원본 `train.csv` 와 1차 parquet 을 대조해 공식을 찾았습니다.
1차 X 의 인덱스가 원본 행 번호를 보존(`[2, 3, 4, …]` — 앞 2행 드롭)해 정렬이 가능했습니다.

```python
# ── 날짜차 파생 4종 ── ⚠ .dt.days 가 아니라 실수 단위다
dt = lambda c: (df["Transaction_Datetime"] - df[c]).dt.total_seconds() / 86400
df["account_age_days"]       = dt("Account_creation_datetime")
df["days_since_last_atm"]    = dt("Last_atm_transaction_datetime")
df["days_since_last_branch"] = dt("Last_bank_branch_transaction_datetime")
df["days_since_resumed"]     = dt("Transaction_resumed_date")

# ── 위협 집계 5종 ──
AUTH = [f"Customer_flag_change_of_authentication_{i}"    for i in range(1, 5)]
MAL  = [f"Customer_flag_terminal_malicious_behavior_{i}" for i in range(1, 7)]
NET  = ["Customer_rooting_jailbreak_indicator", "Customer_VPN_Indicator",
        "Customer_mobile_roaming_indicator",    "Unused_terminal_status"]

df["auth_change_count"]         = df[AUTH].sum(axis=1)
df["terminal_malicious_count"]  = df[MAL].sum(axis=1)
df["device_network_risk_count"] = df[NET].sum(axis=1)
df["threat_total_count"]        = df[MAL + AUTH + NET].sum(axis=1)
df["cert_or_auth_risk"]         = df["First_time_iOS_by_vulnerable_user"]   # ⚠ 아래 참고
```

| 피처 | 일치율 | 상태 |
|---|---|---|
| `account_age_days` | **100.00%** | 확정 |
| `days_since_last_atm` | **100.00%** | 확정 |
| `days_since_last_branch` | **100.00%** | 확정 |
| `days_since_resumed` | **100.00%** | 확정 |
| `auth_change_count` | **100.00%** | 확정 |
| `terminal_malicious_count` | **100.00%** | 확정 |
| `device_network_risk_count` | **100.00%** | 확정 |
| `threat_total_count` | **100.00%** | 확정 |
| `cert_or_auth_risk` | **100.00%** | 확정 ⚠️ **이름과 내용 불일치** |

**주의 2가지**

1. **날짜차는 `.dt.days` 가 아니라 `.total_seconds()/86400`** 입니다.
   정수 절사 버전은 일치율이 **0.02~3.8%** 로 완전히 다릅니다 — 시·분 소수점이 신호를 담고 있습니다.
2. **`cert_or_auth_risk` 는 이름과 내용이 다릅니다.**
   "인증서/인증 위험"이라는 이름과 달리 `First_time_iOS_by_vulnerable_user` 플래그를
   그대로 복사한 값입니다 (96,140행 중 **23행만 1**, 0.024%).
   → [`03a` #A-18](03a_issues_data_modeling.md#a-18)

**`threat_total_count` 는 독립 검증됐습니다** — FeatureBridge 개발 당시
잔차법으로 역산한 공식(*"6그룹 = 단말악성6 + 인증변경4 + 루팅 + VPN + 미사용단말 + 로밍"*)과
이번 대조 결과가 **완전히 일치**합니다 ([`기타 문서/FIX_REPORT.md`](../기타%20문서/FIX_REPORT.md) v5.9).

| IsolationForest 단독 | PR 0.030 / ROC 0.704 | PR **0.0246** / ROC **0.6351** | ✅ 둘 다 매우 약함 |
| LightGBM 지도 단독 | PR 0.916 / ROC 0.997 | PR **0.9330** / ROC **0.9974** | ✅ 압도적 |
| 앙상블 (0.5·0.5) | PR 0.837 / ROC 0.983 | PR **0.8050** / ROC **0.9319** | ✅ 지도 단독보다 나쁨 |

**결론이 그대로 재현됩니다.** 사기 비율 1.08% 이므로 PR-AUC 무작위 기준선은 약 0.011 인데,
ISF 단독은 0.0246 — **무작위보다 2배 나은 정도**입니다.

<a id="r-7"></a>
## R-7. 기획서 M5 — 질문만 있고 답이 없던 항목

**비어 있던 것**
기획서 예상 결과물 3번과 분석 질문 M5 입니다.

> *"이상탐지 모델 + 이상점수 = 정상 기반 ISF, **이상점수를 분류 피처로 결합**"*
> *"M5. 이상 점수가 도움이 되나? — 결합 전/후 비교해 효과를 검증한다"*

`reports/04` 는 ISF 를 **독립 탐지기**로만 평가했고, **피처로 결합한 결과는 어디에도 없습니다.**
3차 통합분석 노트북에도 없습니다.

**실측 결과**

| 구성 | Macro-F1 |
|---|---|
| 3차 58피처 | 0.6138 |
| **+ `iso_score` (59피처)** | **0.6053** (**−0.0084**) |

**M5 에 대한 답: 이상 점수 결합은 이 데이터에서 이득이 없습니다.**

이유는 명확합니다. IsolationForest 는 *"정상 분포에서 얼마나 벗어났는가"* 를 재는데,
LightGBM 이 58피처로 이미 훨씬 정교하게 그 판단을 하고 있습니다 (PR-AUC 0.933 vs 0.025).
약한 신호를 추가하면 트리가 거기에도 분기를 낭비합니다.

> 최종 58피처에 이상 점수 계열이 없는 것은 **누락이 아니라 타당한 결과**입니다.
> 다만 *"안 했다"* 가 아니라 **"해봤고 이득이 없었다"** 로 기록되어야 합니다.

**남은 한계** — ISF 의 진짜 목적은 *"학습 때 못 본 신종 사기"* 탐지인데,
valid 의 사기는 전부 train 에 있는 12유형입니다.
**한 유형을 통째로 빼고 학습해 그 유형을 탐지하는지 보는 실험**(leave-one-type-out)이 있어야
ISF 의 실제 효용을 알 수 있습니다 — 미실행.
