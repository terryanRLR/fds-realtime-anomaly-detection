## 2. 운영 임계값 — 왜 `0.005` 인가

### 현재 설정 ([`watcher_config.json`](../watcher_config.json))

```json
{
  "_version": "v16",
  "dual_threshold": true,
  "th_review": 0.005,
  "th_confirm": 0.9,
  "pii_level": "standard",
  "dedup_hours": 24,
  "_changed_by": "팀 비용분석 검토 반영",
  "_changed_at": "2026-08-05"
}
```

> **설정 파일에 결정 근거를 함께 적습니다.** `_note` 필드가 그 이력을 담습니다 —
> *"기대비용 기반 결정. Macro-F1 ≥ 0.6 제약 하 비용 최소화.
> th_review 0.10 → 0.005: 기대비용 7.48억 → 4.62억(−2.86억), 미탐 44 → 27건,
> 하루 알림 2.8 → 3.7건."*

### 이중 임계값 — 두 목적을 하나로 만족시키려 하지 않았다

| 임계값 | 값 | 목적 | 동작 |
|---|---|---|---|
| `th_review` | **0.005** | **놓치지 않기** (미탐 최소화) | Slack — 사람이 본다 |
| `th_confirm` | **0.90** | **과차단 방지** (확실한 것만) | Slack + **Email** 승격 |

튜터 지적 *"'정상 과차단 방지'와 '13유형 정확 탐지'는 trade-off — 각각 구체적 임계값 필요"* 에 대한 답입니다.
낮은 임계값은 *"일단 사람에게 보여준다"*, 높은 임계값은 *"정식 대응을 시작한다"* 로 **역할이 다릅니다**.

### 비용 모델

```
기대비용 = (미탐 건수 × 1,700만원) + (오탐 건수 × FP 단가)
           보이스피싱 건당 평균 피해액      고객 불편·검토 대응비
```

FP 단가는 시나리오 3종으로 감도분석합니다: **A** 5천 / **B** 1만 / **C** 5만원.

**비대칭 규모** — 미탐 1건 1,700만원 vs 오탐 1건 5천~5만원 = **최대 340배**.

### 채택 논리 — 세 단계

**① 순수 비용최소화의 함정**

제약 없이 비용만 최소화하면 `0.0002`(비용 2.41억)가 나옵니다.
그런데 **Macro-F1 이 0.469 로 무너집니다.**

임계값 `0` 은 더 극단적입니다 — 전량 사기 판정이라 미탐은 0이지만
오탐 23,602건으로 **비용이 11.80억으로 오히려 폭증**합니다.

**② `Macro-F1 ≥ 0.60` 제약을 건다**

> ⚠️ **최종값을 정한 것은 비용이 아니라 이 제약입니다.**
> **"왜 0.6인가"에 답할 수 있어야 합니다** — `model_meta.json` 의 기준선
> **0.6138** 을 지키는 값입니다. 제약을 낮추면 더 싼 임계값이 선택됩니다.

**③ 제약 하 비용 최소** → **0.005** (Macro-F1 0.6030 · 비용 4.62억)

### 성능 최고점(0.03)을 안 쓴 이유

| | 0.005 (채택) | 0.03 (성능 최고) | 차이 |
|---|---|---|---|
| Macro-F1 | 0.6030 | 0.6395 | +0.0365 |
| 미탐 | 27 | 37 | +10건 |
| 오탐 | 69 | 17 | −52건 |
| **기대비용** | **4.62억** | **6.30억** | **+1.68억** |

Macro-F1 이 0.0365 오르는 대가가 **1.68억**입니다.
미탐 10건이 늘어나는데, 미탐 1건이 1,700만원이므로 그것만으로 1.7억입니다.

### 결론의 견고성

> **오탐 1건이 425만원은 되어야** 이전 값(0.10)이 이깁니다. 가정(5만원)의 **85배**입니다.
> 어떤 시나리오를 넣어도 뒤집히지 않습니다.

### ⚠️ 단정하지 말아야 할 것

**0.005 / 0.008 / 0.01 의 비용 차이는 미탐 5건 이내입니다.**
사기 258건 표본에서 이 정도는 **분산 범위일 수 있습니다.**

"0.005 가 최적"이 아니라 **"0.005 근방이 합리적 구간"** 이라고 말하는 것이 정확합니다.

### FN 고정 단가의 한계

유형별 실제 평균 피해액은 `i` 8,097만원 ~ `h` 347만원으로 **23배** 차이입니다.

| 임계값 | 미탐 | 실제금액(억) | 고정값(억) | 차이 |
|---|---|---|---|---|
| 0.0005 | 17 | 4.25 | 2.89 | **+47.1%** |
| 0.001 | 19 | 4.38 | 3.23 | +35.6% |
| **0.005** | 27 | 5.06 | 4.59 | **+10.2%** |
| 0.01 | 31 | 5.32 | 5.27 | +0.9% |
| 0.03 | 37 | 6.04 | 6.29 | −4.0% |

채택 구간(0.005)에서는 차이가 +10.2% 로 상대적으로 작습니다.
**실제 금액으로 계산해도 절감 방향은 같습니다** (0.10 → 8.38억, 0.005 → 5.06억).

### 임계값의 실제 영향력은 생각보다 작다

워처 규칙은 **OR** 입니다.

```
위험점수 ≥ 임계값   OR   예측 유형이 사기(argmax)
```

모델이 argmax 로 사기라 부른 **200건은 임계값과 무관하게 항상 알림**이 갑니다.
임계값이 좌우하는 건 *"유형은 정상인데 점수가 애매한"* **20~30건 구간**뿐입니다.

> **OR 은 의도적입니다.** 무인 경로에서 미탐은 되돌릴 수 없기 때문입니다.

### 재현율 숫자가 두 개인 이유

| 지표 | 의미 | 값 |
|---|---|---|
| **탐지 재현율** | 사기를 **사기로** 잡았나 (유형 무관) | **82.9%** |
| `verify_bundle` 재현율 | 사기를 **정확한 유형으로** 맞췄나 | **53.5%** |

**알림 관점에선 앞, 모델 성능 관점에선 뒤가 맞습니다.**
둘을 섞어 쓰면 안 됩니다.

### 재측정 방법

```bash
python -m tools.threshold_report --daily 300 --fn-cost 1700 --fp-cost 5 --min-macro-f1 0.6
```
