# A. QA 대시보드 (`dashboard.py` 5,843줄 · :8501)

*"이 모델이 쓸 만한가"* 에 답하는 화면입니다.

## A-1. 📋 세션 1 — 프로젝트 개요

**무엇** — 데이터·모델·파이프라인 요약. 전체 건수 · 정상 비율 · 사기 건수/유형 수 · 피처 수.

**어떻게** — 사이드바에서 선택한 데이터셋에 따라 **KPI 가 실시간 변동**합니다.
하드코딩된 숫자가 아니라 선택된 parquet/CSV 에서 계산합니다.
데이터셋 이름·행 수·비고가 캡션으로 표시돼 **어떤 데이터를 보고 있는지** 명확합니다.

사기 유형 13종 각각의 설명 사전이 붙어 있고, [`i18n_data.py`](../i18n_data.py) 에서 문구를 가져옵니다.

> **함정** — 초기에는 그래프가 전부 하드코딩이었습니다.
> `train.csv` 연동으로 바꾸면서 로딩이 느려졌지만, *"데이터에 맞게 변동 가능"* 을 택했습니다
> ([`reports/18`](../reports/18_대시보드_구현내역_일자별.pdf) 2026-07-09).

## A-2. 📊 세션 2 — 모델 성능 (실시간 재평가)

**무엇** — 학습 시점 리포트 + **선택한 (데이터셋 × 모델) 조합으로 지금 재평가**.
모델 최대 3개까지 동시 비교, 13×13 혼동행렬, 기대비용 곡선.

**어디** — [`pipeline/evaluator.py`](../pipeline/evaluator.py) (466줄)

**어떻게**
- 모델별 **자동 프렙 선택** — 기대 피처가 전부 있으면 passthrough, 소량 누락이면 피처 매칭 +
  기본값 대체, 대량 누락 + 브리지가 있으면 브리지 변환 후 매칭
- 임계값 슬라이더 조정 시 KPI · CM · 클래스 리포트가 **실시간 재계산**
  (`risk ≥ threshold` → 원래 유형, 미달 → 정상 `m`)
- 혼동행렬 **2층 히트맵** — 대각선(정탐)은 기존 톤, 오프대각선(오류)은 빨간 강조
- **비율(%) 토글** — 행 기준 %로 전환, 호버에 건수 병기.
  희소 유형의 오탐 패턴이 정상 2만여 건에 묻히지 않고 보인다
- **층화 표본** — 대형셋 샘플링 시 사기 전량 보존 + 정상만 잔여 예산 샘플.
  실측: va 23,860행 → 상한 2,000에서 무작위면 사기 ~21건 vs **층화 258건 전량** (12배 안정)

> **함정 4건**
> - 정수 클래스 vs 문자 라벨 → **전 지표가 정확히 0.0** ([`03b` #B-3](03b_issues_dashboard_pipeline.md#b-3))
> - 유형 A 막대가 안 보임 — 값이 없는 게 아니라 **실제로 0.0** ([`03b` #B-16](03b_issues_dashboard_pipeline.md#b-16))
> - NaN 대체가 macro-F1 을 0.7%p 깎음 ([`03b` #B-9](03b_issues_dashboard_pipeline.md#b-9))
> - 48↔81 피처 불일치 ([`03b` #B-5](03b_issues_dashboard_pipeline.md#b-5))

## A-3. 🔍 세션 3 — 오탐 · 미탐 분석

**무엇** — 임계값별 FP/FN 분포, 세그먼트별 오류율.

**어떻게** — 세그먼트 히트맵 · 금액대 막대에 공통 **비율 토글**.
`label_encoders.pkl` 로 표시용 역변환 (수치 코드 `0/1/2` → `ATM/internet/…`), 실패 시 코드값 유지.

## A-4. 🧪 세션 4 — 합성 데이터 QA

**무엇** — 합성 거래 생성 · 검증. 목표 유형을 골라 생성하면 세션5 로 전송된다.

**어떻게** — 명세서 기반 컬럼별 생성·검증 규칙(값 범위·형식)으로 적합성 검사.
세션4 → 세션5 전송 버튼으로 파이프라인이 이어집니다.

## A-5. 🚀 세션 5 — 실시간 탐지 시연

**무엇** — 단건 탐지 · 배치 일괄 분석 · Slack/Email 발송.

**입력 5종**

| 입력 | 비고 |
|---|---|
| 직접입력 | 🏦 **계좌 이력 필드 노출** + 되돌리기 · 고위험 자동채움 프리셋 |
| `test.csv` | 라벨 없음 |
| `train.csv` | 📄 원본 CSV ↔ 📦 **Parquet 토글** |
| 합성 생성 | 세션4 연계 |
| 폴더 배치 | `inbox/` 로 전송 → 워처가 집는다 |

**단건 예측 분기** — 행의 `_input_mode` 에 따라 자동 선택:
`RowClassifier`(인코딩행) / `BridgedClassifier`(원본+브리지) / `MLClassifier`(기본)

**배치 4탭 UI** (탐지 실행과 동일한 UX)

| 탭 | 내용 |
|---|---|
| 📊 전체 결과 | 건별 판정 DataFrame · ⬇️ CSV 다운로드 |
| 🧾 분석 보고서 | AI 통합 리포트 · 📋 `.txt` 다운로드 |
| 📨 Slack | 미리보기 + 발송 버튼 |
| 📧 Email | HTML 미리보기 + 발송 버튼 |

`🔄 재분석(리롤)` — 같은 데이터로 재실행. 단건↔배치는 **상호 배타**(결과 겹침 해소).

> **함정 3건**

# B. 관제 콘솔 (`ops_dashboard.py` 3,554줄 · :8502)

## B-1. 🧠 AI 분석 · 알림 (첫 화면)

**무엇** — LLM 분석 + 발송. **편집 가능한 미리보기** + 감사 로그.

**어디** — [`pipeline/ops_dispatch.py`](../pipeline/ops_dispatch.py) (730줄) ·
[`pipeline/detect_workbench.py`](../pipeline/detect_workbench.py) (988줄)

**어떻게**
- 발송 전 본문을 **그 자리에서 고칠 수 있다.** 보이는 그대로 나간다
- 모든 발송이 `notify_audit` 테이블에 기록 (자동/수동 구분)
- 삭제는 **2단계 확인** + 삭제 흔적도 기록
- AI 분석 자동/수동 토글

> **함정** — *"미리보기는 옛 본문인데 전송은 새 본문이 나갔다."*
> Streamlit 이 `key` 가 있으면 `value=` 를 무시하기 때문
> → [`03b` #B-11](03b_issues_dashboard_pipeline.md#b-11). **이 저장소에서 가장 비싼 교훈.**

## B-2. 🚨 알림 트리아지

**무엇** — 판정 대기 큐 → 건별로 **정탐/오탐/미탐/보류** 찍기 + 사유·메모 + 재검증.

**어디** — [`pipeline/review_store.py`](../pipeline/review_store.py) (807줄)

**설계 결정 2가지**

**① append-only** — 판정을 `UPDATE` 하지 않는다. 재판정하면 새 행이 쌓이고 최신 행이 현재 판정.

**② 판정 시점 스냅샷 동봉** — 임계값은 핫 리로드된다.
`th_review=0.45` 에서 내린 "오탐"과 `0.60` 에서 내린 "오탐"은 비교 불가.
**스냅샷이 없으면 임계값 시뮬레이터가 전부 거짓말이 된다.**

**오탐 사유 코드** — 사유 없는 오탐률은 행동으로 이어지지 않는다.

| 코드 | 의미 | 처방 |
|---|---|---|
| `legit_customer` | 정상 고객 확인됨 | → **임계값**을 올려라 |
| `known_pattern` | 기존 예외 패턴 (해외출장·급여일) | → 예외 규칙 |
| `test_data` | 테스트/내부 거래 | → 필터 |
| `data_error` | 데이터 오류·중복 유입 | → 파이프라인 |
| `model_drift` | 모델 오작동 의심 | → **재학습** |
| `rule_overfit` | 룰 과민반응 | → 규칙 조정 |
| `other` | 기타 | |

> `legit_customer` 가 많으면 임계값 문제, `model_drift` 가 많으면 재학습 문제.
> **처방이 완전히 다르다.**

**동시 판정 잠금** — 여러 명이 교대로 쓸 때 같은 건을 두 명이 잡지 않도록.
15분 TTL, `st.fragment` **하트비트**로 조사 중에는 갱신 ([`03c` #C-21](03c_issues_ops_runtime.md#c-21)).
타인 잠금 시 경고 표시 + `🔓 잠금 무시하고 내가 검토` 선택 가능.

**상태 영속** — 메모는 `review_draft` 테이블에 임시저장.
새로고침해도 복원되고, 초안은 사람별로 격리됩니다.

**주요 API**

| 함수 | 설명 |
|---|---|
| `record(db, txn_id, verdict, ...)` | 판정 1건 |
| `record_many(db, items)` | 일괄 (단일 트랜잭션) |
| `current(db, txn_ids)` | txn_id 별 **최신** 판정 |
| `history(db, txn_id)` | 판정 이력 전체 (감사용) |
| `counts(db, since_hours)` | 집계 + 오탐률 |
| `export_training_labels(db)` | **재학습용 라벨 + 피처** |
| `undo_last(db, txn_id)` | 유일한 파괴적 연산 |

> 이 탭이 *"이 값이 이 판정의 실제 기준이었습니다"* 를 명시합니다.

> **함정** — 검색이 "최근 N건 안에서만" 동작했습니다 (필터가 `LIMIT` **뒤**에 걸림)

## B-7. ⚙ 임계값 튜닝

**무엇** — **실제 담당자 판정** 기반 what-if 시뮬레이터 → `watcher_config.json` 즉시 적용.

**QA 대시보드의 비용곡선과 다른 점**

| | QA 대시보드 세션2 | 관제 콘솔 튜닝 탭 |
|---|---|---|
| 근거 | 검증셋 (정적 라벨) | **실제 판정** |
| 분포 | 학습 시점 | **운영 시점** |

**선택 편향 경고 — 그리지 않는 대신 회색으로 그린다**

우리는 **실제로 알림이 나간 거래만** 관측합니다.
과거 `th_review` 아래로 깔려서 알림이 안 간 거래에는 판정이 없습니다.

| 구간 | 신뢰도 |
|---|---|
| τ ≥ 과거 최저 `th_review` | ✅ 신뢰 가능 — 알림을 **줄였을 때**의 효과 |
| τ < 과거 최저 `th_review` | ❌ **데이터 없음** |

화면에서 **회색 점선 + 경계선**으로 표시합니다.
**그냥 그리면 그럴듯한 거짓말이 되기 때문입니다.**

**미탐 반영 곡선** — 기존 곡선을 덮어쓰지 않고 `threshold_whatif_fn()` **별도 함수**로 겹쳐 그립니다.

**확인 카드** — 임계값 저장은 되돌릴 수 없으므로 저장 전 카드를 띄웁니다:
현재→변경 대조표 · 알림/놓친사기 증감 · 신뢰불가 구간 경고 · `watcher_config.json` 에 기록될 결정 근거.

> **함정** — 슬라이더 `step=0.01` 이 운영값 `0.005` 를 만들 수 없었습니다.
> `[적용]` 만 눌러도 임계값이 2배가 되고, **예외는 안 납니다.**
> → [`03c` #C-11](03c_issues_ops_runtime.md#c-11). 지금은 `정확한 값` 숫자 칸(`step=0.001`)이 실제 적용값입니다.

**임계값 대조표** — `ui.threshold_matrix()` 가 사이드바와 튜닝 탭에서
*"왜 임계값이 3개인가"* 를 화면이 직접 답합니다 ([`03c` #C-8](03c_issues_ops_runtime.md#c-8)).

## C-1. 판정 엔진 — `DetectService`

**어디** — [`pipeline/detect_service.py`](../pipeline/detect_service.py) (794줄)

**무엇** — 두 앱과 워처가 공유하는 **단일 판정 경로**. Streamlit 과 무관하게 동작합니다.

```
risk = 1 − P(정상 m)
예측 유형 = 정상 제외 최고확률 클래스

risk < th_review (0.005)              → none    발송 없음
th_review ≤ risk < th_confirm (0.90)  → review  Slack
risk ≥ th_confirm                     → confirm Slack + Email
```

**워처 규칙은 OR 이다**

```
위험점수 ≥ 임계값   OR   예측 유형이 사기
```

모델이 argmax 로 사기라 부른 **200건은 임계값과 무관하게 항상 알림**이 갑니다.
임계값이 좌우하는 건 *"유형은 정상인데 점수가 애매한"* 20~30건 구간뿐입니다.

> **OR 은 의도적입니다.** 무인 경로에서 미탐은 되돌릴 수 없기 때문입니다.

**`allow_dummy=False`** — 모델 로드 실패 시 더미로 돌지 않고 거부합니다
([`03c` #C-6](03c_issues_ops_runtime.md#c-6)).

| 피처 | 복원한 규칙 | 방법 |
|---|---|---|

| `threat_total_count` | 6그룹 합 (단말악성6+인증변경4+루팅+VPN+미사용단말+로밍) | 잔차법 |

**성적 (X_va 23,860행 완전 홀드아웃)**

| 항목 | 결과 |
|---|---|

## C-7. 실시간 경보 시스템

**어디** — [`pipeline/ops_alert.py`](../pipeline/ops_alert.py) (919줄)

**무엇** — 워처가 새 이상거래를 넣으면 **어느 탭에 있든** 화면 위에 경보 카드가 뜨고,
사이렌이 울리고, 브라우저 알림이 나갑니다. 클릭하면 해당 거래의 트리아지로 이동합니다.

### 이 모듈의 절반은 '덜 울리게 하는' 코드다

> **알람 시스템은 기능이 부족해서 죽지 않는다. 과해서 죽는다.**

**실측 소음 예보 (오탐률 37% 기준)**

| 등급 설정 | 하루 알람 | 그중 헛알람 |
|---|---|---|
| `confirm` ← **기본값** | 3.1회 | **1.1회** |
| `review` | 7.0회 | **2.6회** |

**이 예보를 토글 옆에 실시간으로 보여줍니다.** 켤 때 대가를 알아야 계속 켜 둡니다.

**억제 장치 5종**

| 장치 | 기본값 | 이유 |
|---|---|---|
| 등급 필터 | `confirm` | review 까지 울리면 소음 2배 |
| 워터마크 (`transactions.id`) | 자동 | **최초 실행 시 과거 전체가 울리는 사고 방지** |
| 중복 억제 | 30분 | 같은 거래 재유입 |
| 버스트 상한 | 3건/폴링 | 대량 유입 시 100번 울리지 않게 |
| 조용한 시간대 | 미사용 | 야간 무음 |

### 기술적 함정 3가지 — 전부 실제로 밟았다

**① 브라우저 오디오 정책** — `AudioContext` 가 `suspended` 로 생성되고
**에러 없이 조용히** 실패합니다. → 첫 `pointerdown`/`keydown` 에 **자동 무장**
([`03c` #C-9](03c_issues_ops_runtime.md#c-9))

**② 윈도우 알림이 어느 PC 에 뜨는가**

| 방식 | 뜨는 위치 | 채택 |
|---|---|---|
| 브라우저 `Notification` API | **보는 사람 PC** | ✅ |
| 파이썬 `win10toast` | **서버 PC** | ❌ ngrok 공유 시 아무도 못 봄 |

**③ 주입 HTML 버튼은 못 쓴다** — iframe realm 이 리런마다 파괴되어
`onclick` 과 `setTimeout` 이 죽습니다. **카드 DOM 은 부모에 남아 화면에는 그대로 보입니다.**
→ 클릭이 필요한 것은 전부 `st.button` ([`03c` #C-10](03c_issues_ops_runtime.md#c-10))

### 클릭 → 이동

Streamlit 은 JS 이벤트를 직접 받지 못합니다.
경보 카드가 `?goto=TXN_xxx` 로 쿼리 파라미터를 바꾸면 재실행이 걸리고,
`st.query_params` 로 읽어 트리아지 탭에서 해당 건을 펼칩니다.
**필터에 걸려 안 보이는 건이면 큐에 강제로 끌어올립니다** —
클릭했는데 빈 화면이 나오는 것이 최악의 경험이기 때문입니다.

### ♿ 접근성

- 초당 3회를 넘는 점멸은 **광과민성 발작**을 유발할 수 있습니다 (WCAG 2.3.1).
  번쩍이는 빨간 화면 대신 **레이더 스윕**(회전, 점멸 없음), 펄스 주기 1.4초
- `prefers-reduced-motion: reduce` 를 존중해 모든 애니메이션을 끕니다
- 사운드는 **삼각파 + 게인 엔벨로프**. 사각파는 귀에 꽂히지만 야간 관제실에서 거슬리고,
  엔벨로프가 없으면 시작·끝에 '툭' 하는 클릭 노이즈가 납니다

## C-8. 분석 캐시

**어디** — [`pipeline/analysis_store.py`](../pipeline/analysis_store.py) (501줄)

**메우는 구멍** — `detect_service.detect()` 는 13클래스 확률 · LLM 리포트 4종 ·
마스킹 원거래 · RAG 근거를 계산하는데, `_save_db()` 가 남기는 것은 **6개 컬럼뿐**입니다.

> **LLM 이 쓴 판정 근거는 Slack 을 보내는 순간 사라집니다.**
> LLM 을 돌리는 이유 자체가 그 분석인데 DB 에 한 글자도 남지 않습니다.

**붙이는 법 — 워처에 2줄**

```python
from pipeline import analysis_store as astore
astore.attach(svc)     # DetectService 생성 직후
```

`attach()` 는 인스턴스의 `detect` 를 감싸는 래퍼라 기존 파일 본문은 손대지 않습니다.

**설계 결정**

| 결정 | 이유 |
|---|---|
| append-only | UPSERT 로 근거가 덮어써지는 사고를 반복하지 않는다 |
| **zlib 압축** | 건당 1~4KB · 실측 압축률 **0.567** → 하루 100건이면 **연 53MB** |
| 이상거래만 | 정상 거래는 LLM 도 안 돌았다. 용량만 먹는다 |
| 저장 직전 재마스킹 | 심층 방어 (DB 파일 바이트 검사로 검증) |
| 실패해도 탐지 계속 | 캐시는 부가 기능. 저장 실패로 알림이 막히면 본말전도 |
| **판정된 건은 보존** | `prune()` 이 나이로 지울 때 판정이 달린 거래는 제외 — 감사 자료이자 재학습 라벨의 출처 |
| **당시 환경 동봉** | 임계값이 핫 리로드되므로 지금 값이 이 판정의 기준이 아닐 수 있다 |

**정직한 안내** — 훅을 붙이기 전 탐지분은 **복원 불가능**합니다.
로그 화면이 그 사실을 명시적으로 안내합니다 (조용히 빈 화면을 보여주지 않습니다).

| 분류 | 예 | 승인 게이트 |
|---|---|---|

| **워처 제어** | 시작/중지 | **승인 카드 + 3중 방어** |

**★ 새로 막은 축 — 경보 등급 임계값**

`th_review`/`th_confirm` 저장은 표면상 화면 설정이라 넣을 뻔했습니다.
그런데 이 값은 `watcher_config.json` 에 저장되고 그 파일은 **핫 리로드**입니다 —
저장하는 순간 재시작 없이 **무인 워처의 경보 기준이 바뀝니다.**
실질적으로 워처 제어라 레지스트리에서 제외하고, 사람이 비용곡선을 보고 직접 누르는 쪽으로 남겼습니다.

**주입되는 사실** — 매 턴 현재 상태(워처 생존 · 미판정 건수 · 임계값 · 모델)를 컨텍스트에 넣습니다.
그래서 *"현재 판정을 기다리고 있는 거래는 총 200건입니다"* 같은 **라이브 DB 조회 답변**이 가능합니다.

**자가진단 체인** — 순서에 의미가 있습니다. LLM 없이 파서를 왕복 검증하므로,
여기서 초록불인데 액션이 안 먹으면 원인은 **LLM 연결**이라고 가려낼 수 있습니다.

> **함정** — `sort_queue` 가 **죽어 있었습니다.**
> *"위험점수 순으로 정렬해줘"* 에 챗봇은 "바꿨습니다"라고 답하는데 화면은 그대로.
> 구버전 값 정리 코드가 `ss["tri_sort"] = "점수순"`(화면 표시 문구)을
> `_SORT_OPTS = ["age","score"]` 에 없다고 **매번 조용히 버렸습니다.**
> 지금은 25종 전수에 대해 "상태가 실제로 바뀌고 메모가 나오는가"를 검사합니다.

## C-10. 다국어 (KO / EN / JA / ZH)

**어디** — [`i18n_data.py`](../i18n_data.py) (1,705줄) · `pipeline/ops_ui.py` `_OPS` 표

**규모** — **772키 × 4개 언어** (`i18n_data.TR`, `I18N_VERSION = v9.3`). 네 언어가 모두 같은 키 집합을 갖는다(누락 0).

**전략 — `i18n_data.py` 를 수정하지 않는다**

```
신규 문구 (오탐 판정 등)  → ops_ui._OPS 표 (4개국어 직접 정의)
기존 문구 (사기 유형명 등) → i18n_data 에 위임
어디에도 없으면          → 키를 그대로 반환
```

`i18n_data.py` 가 없거나 구버전이어도 **한국어로는 동작**합니다 (`HAS_I18N_DATA=False`).

> **사기 유형명은 반드시 `i18n_data` 에서 가져옵니다.**
> 같은 제품인데 세션3 에선 "위장 최종인출", 관제 화면에선 다른 말이면 곤란합니다.

**진행 이력** — 영어 화면의 한국어 잔여: **94 → 5** (v28~v37, 8단계 작업).
남은 5개는 계좌이력 필드명이며 **의도적 보류**입니다 ([`03c` #C-28](03c_issues_ops_runtime.md#c-28)).

**검증** — 4개국어 × 7테마 = **28조합 전부 예외 0** (AppTest).

> **함정** — 비한국어 화면에서 **두 번째** `run()` 을 하면 AppTest 하네스가 죽습니다.
> 실제 브라우저는 멀쩡하지만 **i18n 회귀를 자동으로 못 잡습니다**
> → [`03c` #C-27](03c_issues_ops_runtime.md#c-27) (미해결)
