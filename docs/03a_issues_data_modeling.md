## A-1. 🔴 `is_fraud` 라벨 누수 — Macro-F1 0.7103 이 거짓이었다

**증상**
중간보고에 Macro-F1 **0.7103** 으로 보고. 멘토가 *"group split 을 설계했으니 누수 통제는 돼 있을 텐데
0.7103 은 어디서 나온 데이터 수치인지 인지가 잘 안 된다"* 고 질문.

**재현 조건**
전처리 노트북에서 통계 검정용으로 만든 이진화 데이터프레임(`train_binary`, `is_fraud` 컬럼 포함)을
`df` 로 받아 두고, **파생변수 생성 단계 이후까지 그 `df` 를 계속 사용**할 때.
파생변수를 붙이는 대상이 원본 `train` 이 아니라 `is_fraud` 가 섞인 프레임이 되므로,
최종 피처 목록에 정답 라벨이 그대로 들어간다.

**원인 진단**
§11(통계 검정)에서 정상 `m` vs 사기 `a~l` 이진 비교를 하려고 `is_fraud` 를 만들었다.
이건 **검정용 임시 컬럼**이었지, 학습 피처가 아니었다.
그런데 §13(파생변수 생성)이 같은 `df` 를 이어받으면서 임시 컬럼이 살아남았다.

`is_fraud` 는 타깃의 이진화 버전이므로, 모델은 "정상인가 아닌가"를 **공짜로** 알게 된다.
13클래스 중 정상 `m` 이 99%라, 이 한 컬럼이 사실상 문제의 절반을 푼다.

**해결**
```python
df = train.copy()                       # ① 원본에서 재시작
drop_cols_final = [..., 'is_fraud']     # ② 방어적으로 한 번 더 제거
```

|---|---|---|

| 차이 | | **−0.0965** |

**재발 방지 — 코드에 가드를 박았다**
```python

_drop = [c for c in X_tr.columns if c.lower() in [s.lower() for s in LEAK_COLS]]
```

## A-2. 🔴 look-ahead 의심 피처 5개 — 명세 해석으로 유지했으나 미확정

**증상**
통합분석 노트북을 실행할 때마다 경고가 뜬다.

```
[경고] look-ahead 의심 피처 잔존: ['Account_one_month_max_amount', 'Account_one_month_std_dev',
       'Account_dawn_one_month_max_amount', 'Account_dawn_one_month_std_dev',
       'Amount_vs_monthly_max_ratio']
       → as-of(시점까지 누적) 재설계 여부 전처리팀 확인 필요
```

**재현 조건**
`X_tr.parquet` 에 위 5개 컬럼 중 하나라도 남아 있으면 항상 발생.
현재 3차 전처리 58피처에 **5개 전부** 존재한다.

**원인 진단 (튜터 원문)**
> *"`Amount_vs_monthly_max_ratio` — 거래 시점에는 해당 월이 종료되지 않아 '월간 최대 거래 금액'을
> 확정할 수 없음. 이는 미래 데이터를 참조하는 논리적 오류를 발생시킬 수 있으므로,
> 실제 시스템 운영 환경을 고려하여 산출 방식(예: 전월 기준 또는 현재 시점까지의 누적 최대값 등)에 대한
> 재검토 필요."*

운영 환경에서 8월 15일 거래를 판정하는 시점에 "8월 최대 거래금액"은 아직 확정되지 않았다.
학습 데이터에서는 알 수 있지만 **운영에서는 알 수 없는 값**이다.

**팀의 대응**
데이터 명세서상 해당 컬럼이 **"거래 기준 1개월 이전"** 을 뜻한다고 해석하고 유지.
즉 미래가 아니라 **과거 1개월**이라는 판단.

**왜 완전히 닫히지 않았나**
1. 명세 해석이 **검증되지 않았다.** 원본 데이터 제공자에게 확인한 기록이 없다.
2. 팀 스스로 확신하지 못해 **코드에 상수와 경고를 남겼다** (`LOOKAHEAD_SUSPECT`).
3. 최종 요약에도 `⚠️ look-ahead 잔존: 5개 (as-of 재설계 후 재측정 필요)` 가 출력된다.

**영향 범위 — 제거하면 성능이 크게 흔들린다**

| 피처 | SHAP 순위 | mean\|SHAP\| |
|---|---|---|
| `Amount_vs_monthly_max_ratio` | **5위** | 0.2288 |
| `Account_one_month_std_dev` | **7위** | 0.2040 |
| `Account_one_month_max_amount` | 14위 | 0.0967 |

15개 상위 피처 중 3개가 이 목록에 있다.

**남은 일**
`as-of`(거래 시점까지의 누적 최대값) 방식으로 재설계 후 재측정.
데이터 명세서 원문 확인이 선행되어야 한다.

## A-3. 🟠 2계층 구조의 오류 전파 — 1단계 FN 이 영구 미탐이 된다

**증상**
기획서가 예상 결과물 1번으로 지목한 2단계 계층 분류가, 실측에서 한방 기본보다도 낮게 나왔다.

**재현 조건**
```
stage1: LGBM 이진 (정상 vs 사기)
stage2: LGBM 12유형 (사기 데이터만 학습)
판정  : stage1 확률 ≥ thr 이면 stage2 로 유형 결정, 아니면 정상
```
동일 valid 홀드아웃 23,860행.

**원인 진단**
stage1 에서 정상으로 걸러진 건은 **stage2 가 볼 기회조차 없다.**
1단계의 False Negative 가 그대로 최종 미탐으로 굳는다 — 회복 경로가 없다.

한방 구조에서는 13클래스 확률이 한 번에 나오므로, 정상 확률이 애매한 건도
`risk = 1 − P(m)` 로 사후에 건져낼 수 있다.

**실측**

| 모델 | 임계값 | Macro-F1 | 미탐 | 오탐 |
|---|---|---|---|---|
| 한방 (argmax) | — | 0.6138 | 59 | 1 |
| **한방 + 임계값** | **0.03** | **0.6395** | 37 | 17 |
| 2계층 | 0.5 | 0.6105 | 43 | **51** |
| 2계층 + 임계값 | 0.5 | 0.6105 | 43 | 51 |

> **2계층 + 임계값 조정의 최적점이 기본값 0.5 와 같다**는 것이 결정적이다.
> 임계값을 어떻게 움직여도 좋아지지 않는다 = stage1 확률 분포에 끌어올릴 여지가 없다.

**해결/결정**
**한방 + 사후 임계값 조정 채택.** 오류 전파 없이 임계값 유연성만 취한다.

발표자료 p.21

## A-4. 🟠 임계값 0 에서 Macro-F1 붕괴 — 그런데 '구간'이 아니라 '한 점'이었다

**증상**
임계값을 낮출수록 미탐이 줄어드는데, 0 근처에서 Macro-F1 이 **0.021** 로 붕괴한다.
동시에 기대비용도 **11.80억**으로 오히려 폭증한다.

**재현 조건**
`risk = 1 − P(m) ≥ thr` 판정에서 `thr = 0`.
`risk` 는 확률이므로 항상 0 이상 → **전량 사기 판정** (23,602건 전부 오탐).

**원인 진단**
`>=` 비교라 `risk ≥ 0` 은 모든 행에 대해 참이다.
"위험점수가 0 이상이면 사기"는 사실상 필터가 없는 것과 같다.

**추가 조사 — 붕괴가 넓은 구간인가?**
0 ~ 0.0002 를 정밀 스캔했다.

| 임계값 | Macro-F1 | 미탐 | 오탐 |
|---|---|---|---|
| 0.000000 | **0.0210** | 0 | **23,602** |
| 0.000010 | 0.2659 | 1 | 1,810 |
| 0.000020 | 0.3028 | 3 | 1,348 |
| 0.000050 | 0.3633 | 5 | 832 |
| 0.000100 | 0.4194 | 7 | 578 |
| 0.000200 | 0.4690 | 13 | 389 |

**붕괴는 임계값 0 한 점에서만 일어난다.** 0.00001(십만분의 1)만 되어도 오탐이 23,602 → 1,810 으로 급감한다.

**해결/결정**
임계값 격자에서 0 을 특수 케이스로 인지하고, 채택 후보에서 제외.
노트북 출력에 주의 문구를 남겼다 — *"임계값은 소수 6자리 — 0의 개수 주의(0.000010=십만분의1, 0.000100=만분의1)"*

> **이 주의 문구 자체가 실무적입니다.** `0.00001` 과 `0.0001` 은 눈으로 구분하기 어렵고,
> 이 구간에서는 자릿수 하나가 오탐 1,232건 차이를 만듭니다.

## A-5. 🟠 FN 고정 단가 가정이 실제와 최대 47% 어긋난다

**증상**
미탐 1건당 1,700만원(보이스피싱 평균 피해액)으로 고정 계산했는데,
유형별 실제 거래금액을 반영하면 임계값에 따라 크게 어긋난다.

**재현 조건**
`기대비용 = FN 건수 × 1,700만원` 으로 계산할 때. 임계값이 낮을수록 오차가 커진다.

**원인 진단**
유형별 평균 거래금액 편차가 극단적이다.

| 유형 | 평균 거래금액 |
|---|---|
| `i` | **8,097만원** |
| `h` | 347만원 |
| 배수 | **23배** |

낮은 임계값에서는 고액 유형(`i`)이 먼저 잡히므로 남은 미탐의 구성이 달라진다.

**실측 — 실제금액 vs 고정값**

| 임계값 | 미탐 | 실제금액(억) | 고정값(억) | 차이 |
|---|---|---|---|---|
| 0.0002 | 13 | 3.15 | 2.21 | **+42.5%** |
| 0.0005 | 17 | 4.25 | 2.89 | **+47.1%** |
| 0.001 | 19 | 4.38 | 3.23 | +35.6% |
| 0.005 | 27 | 5.06 | 4.59 | +10.2% |
| 0.01 | 31 | 5.32 | 5.27 | +0.9% |
| 0.03 | 37 | 6.04 | 6.29 | −4.0% |

**해결/완화**
고정 단가를 유지하되 **실제금액 대조표를 함께 산출**해 편차를 명시.
채택 임계값 0.005 구간에서는 차이가 +10.2% 로 상대적으로 작다는 것을 확인했다.

**남은 한계**
유형별 단가를 실제로 반영한 최적화는 하지 않았다.
비용 함수를 유형 가중으로 바꾸면 채택 임계값이 달라질 수 있다.

## A-6. 🟠 생성 AI 증강이 오히려 성능을 떨어뜨렸다

**증상**
기획서 목표였던 CTGAN 합성 증강이 baseline 을 넘지 못했다. TVAE·SMOTE 도 마찬가지.

**재현 조건**
```
학습셋  정상 20,000 다운샘플 + 사기 942 = 20,942행
생성    유형당 500건까지 (원본 100건 → +400건)
epochs  300
검증    원본 valid 23,860행 (합성 미포함)
```

**해결/결정**

## A-16. 🟡 이상탐지(ISF) — 실행됐으나 결합 결과는 없었다

> ⚠️ **이 항목은 정정됐습니다.** 초기에는 "미실행"으로 기록했으나,
> [`reports/04`](../reports/04_Baseline_5모델비교_최종모델선정.pdf) §3-3 에 **1주차 실행 기록**이 있습니다.

**증상**
최종 58피처에 이상점수 계열 피처가 없고, 3차 통합분석 노트북에도 ISF 코드가 없다.
기획서 분석 질문 M5 *"이상 점수가 도움이 되나?"* 에 대한 답이 어디에도 없다.

**확인한 것**

| 위치 | 결과 |
|---|---|
| `reports/04` §3-3 | ✅ **1주차(2026-06-29~07-03)에 실행** — PR-AUC 0.030 / ROC 0.704 |
| 3차 통합분석 노트북 | ISF 코드 없음 |
| **이상점수를 피처로 결합한 결과** | ❌ **어디에도 없음** |

**원인 진단**
ISF 는 **독립 탐지기**로만 평가됐다. 기획서가 요구한 것은
*"이상점수를 **분류 피처로 결합**"* 인데, 그 실험은 수행되지 않았다.
1주차 결론(*"단독 대체가 아니라 보완재"*)에서 멈추고 3차로 이어지지 않았다.

**해결 — 이 저장소에서 실측으로 답함**
→ [`notebooks/team_final/11_baseline_and_anomaly_score.ipynb`](../notebooks/team_final/11_baseline_and_anomaly_score.ipynb)

**① ISF 단독 성능 재현 (3차 58피처)**

| 방식 | `reports/04` (1주차) | 재현 | 결론 |
|---|---|---|---|
| IsolationForest 단독 | PR 0.030 / ROC 0.704 | PR **0.0246** / ROC **0.6351** | 매우 약함 |
| LightGBM 지도 단독 | PR 0.916 / ROC 0.997 | PR **0.9330** / ROC **0.9974** | 압도적 |
| 앙상블 (0.5·0.5) | PR 0.837 / ROC 0.983 | PR **0.8050** / ROC **0.9319** | **지도 단독보다 나쁨** |

사기 비율 1.08% 이므로 PR-AUC 무작위 기준선은 약 0.011 — ISF 단독은 **무작위의 2배 수준**이다.

**② M5 에 대한 답 — 피처 결합**

| 구성 | Macro-F1 |
|---|---|
| 3차 58피처 | 0.6138 |
| **+ `iso_score` (59피처)** | **0.6053 (−0.0084)** |

**이득이 없다.** LightGBM 이 58피처로 이미 훨씬 정교하게 "정상에서 벗어난 정도"를 판단하고 있어
(PR-AUC 0.933 vs 0.025), 약한 신호를 추가하면 트리가 거기에 분기를 낭비한다.

> 최종 58피처에 이상점수가 없는 것은 **누락이 아니라 타당한 결과**다.
> 다만 *"안 했다"* 가 아니라 **"해봤고 이득이 없었다"** 로 기록되어야 한다.

**남은 한계**
ISF 의 진짜 목적은 *"학습 때 못 본 신종 사기"* 탐지인데, valid 의 사기는 전부 train 에 있는 12유형이다.
**leave-one-type-out**(한 유형을 통째로 빼고 학습해 그 유형을 탐지하는지) 검증이 있어야
ISF 의 실제 효용을 알 수 있다 — 미실행.

## A-17. 🔴 3차 전처리에서 실질 신호 9개가 함께 사라졌다
