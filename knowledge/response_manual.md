# 이상거래 대응 매뉴얼

위험점수는 `1 - P(정상)`이다. 구간별 기본 조치는 아래를 따르고, 유형별 세부 조치는 `fraud_types.md`의 해당 유형 절을 함께 적용한다.

## 위험점수 구간별 조치

[대응 매뉴얼 — 위험점수 0.90 이상] 조치: 즉시 거래 차단 + 보안팀 에스컬레이션 + 고객 직접 통화 확인
- 후속: 차단 사유와 유형 근거를 사고 이력 DB에 기록. 고객에게 재개 절차 안내.

[대응 매뉴얼 — 위험점수 0.70 ~ 0.90] 조치: 거래 보류 + 추가 인증(OTP/생체) 요구
- 후속: 인증 성공 시 진행, 실패·미응답 시 차단으로 승격.

[대응 매뉴얼 — 위험점수 0.50 ~ 0.70] 조치: 모니터링 강화 + 알림 발송 + 수동 검토 대기열 등록
- 후속: 동일 계좌에서 24시간 내 재발생 시 임계 한 단계 상향 적용.

[대응 매뉴얼 — 위험점수 0.30 ~ 0.50] 조치: 통과시키되 로그 상세 기록
- 후속: 규칙 적합도 지수가 1.5 이상인 건은 대기열에 함께 올림 (모델·규칙 불일치 구간).

[대응 매뉴얼 — 위험점수 0.30 미만] 조치: 정상 처리
- 후속: 조치 불필요.

## 모델과 규칙이 불일치할 때

규칙 체크리스트의 **적합도 지수**가 모델 예측 유형보다 1.3배 이상 높은 다른 유형을 지목하면, 위험점수와 무관하게 **수동 검토 대기열**에 올린다. 실측에서 이 신호가 모델 오분류를 잡아낸 사례가 있다 (모델 d형 예측 → 규칙 j형 지수 2.03 → 정답 j형).

## 공통 조치

- 거래 ID·예측 유형·위험점수·규칙 충족 항목을 사고 이력 DB에 함께 기록
- 고객에게 이상거래 안내 발송 (연락 수단은 유형별 지침 참조 — 탈취 가능한 채널 회피)
- 동일 계좌·단말·수취계좌에서 3회 이상 반복 시 계좌 일시 정지
- 차단·통과 결과를 라벨링해 재학습 데이터로 축적 (유형당 학습 표본이 100건뿐이라 데이터 축적이 성능 개선의 최단 경로)

## 데이터 한계 (보고서에 단정적으로 쓰지 말 것)

- **단말 감염 시점 정보 없음** → e/g/f의 단계 순서는 가설이다
- **유형당 학습 표본 100건** → d·i·l형은 모델 F1이 낮다(l형 0.083). 사람 개입을 전제로 운영
- **d형은 정의 미완성** → 'd형'은 '신호가 약해 확신하기 어렵다'로 읽는다
